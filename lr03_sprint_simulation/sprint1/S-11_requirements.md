# S-11. Правила керування базами практики

Дата підготовки: 2026-10-29.
Стан: чернетка, перевірена на відповідність беклогу. Відкриті питання ще не погоджені.

## Для кого і навіщо

Адміністратор додає та редагує бази практики, щоб оновлювати перелік організацій без допомоги розробника.

## Дані бази практики

| Поле | Обов’язкове | Правило |
| --- | --- | --- |
| Ідентифікатор | Так | Унікальний, не змінюється після створення |
| Назва | Так | Не може бути порожньою або містити тільки пробіли |
| Контактна адреса | Так | Не може бути порожньою або містити тільки пробіли |
| Активність | Так | Активна або неактивна |

Унікальний ідентифікатор — моє уточнення для збереження зв’язку бази з попередніми заявками.

## Правила роботи

1. Адміністратор може додати базу з назвою та контактною адресою.
2. Активна база доступна для вибору в новій заявці.
3. Редагування змінює наявний запис, а не створює новий.
4. Неактивна база недоступна для нових заявок.
5. Вимкнення бази не видаляє попередні заявки.
6. За відсутності обов’язкового поля дані не зберігаються. Користувач бачить назву незаповненого поля.

## Сценарії приймання

| № | Дія | Очікуваний результат |
| --- | --- | --- |
| 1 | Додати активну базу з назвою та контактом | База збережена та доступна для нової заявки |
| 2 | Змінити назву бази | Назва оновлена, ідентифікатор збережений, другого запису немає |
| 3 | Вимкнути базу з попередніми заявками | Нову заявку на неї подати не можна, попередні заявки залишилися |
| 4 | Зберегти базу без назви | Дані не збережені, показано «Вкажіть назву» |
| 5 | Зберегти базу без контакту | Дані не збережені, показано «Вкажіть контактну адресу» |

Тексти повідомлень про помилки — моя пропозиція для цієї історії.

## Відкриті питання

- Що саме означає контактна адреса: електронна пошта чи поштова адреса?
- Чи дозволені дві бази з однаковою назвою?
- Чи потрібне погодження додавання нової бази та хто його надає?

Відповіді поки не отримані. Рішення замовника не вигадую.

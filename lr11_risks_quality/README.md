Нових ризиків під час цього перегляду не додано. Питання, виявлені під час підготовки другого спринта, уже враховані в первинних R-04 і R-05. Саме повторення відомого ризику не є підставою створювати ще один рядок.

Закритих ризиків немає. Для R-01 і R-04 оцінки зменшилися, але відповідні ситуації можуть повторитися під час підготовки наступних історій.

Запис про блокер S-03 у журналі залишається елементом сценарію, тому я не використовую його як підтверджену підставу для статусу realized.

Наступний перегляд проведу після опрацювання події курсу та ухвалення рішення щодо складу REL-1. Якщо раніше спрацює конкретний тригер, відповідний ризик перегляну одразу.

## 3. Definition of Done

Файл dod.md, умов у списку: 6.

Мій DoD визначає готовність навчальних матеріалів: відповідність критеріям беклогу, повноту користувацького потоку, перевірку помилкових дій і доступу, готовність залежностей та зафіксований результат самоперевірки.

Обов’язкове review другою людиною я замінила повторною самоперевіркою за чеклістом. Це дозволяє застосовувати стандарт в індивідуальному проєкті, не роблячи кожне закриття історії винятком.

DoD не підміняє критерії приймання. Наприклад, обмеження PDF до 20 МБ належить до S-06, а перевірка відповідності матеріалів критеріям є спільною умовою для всіх історій.

Порівняння з точним формулюванням DoD у ЛР2 ще потрібно виконати за актуальним lr02_approach/README.md.

## 4. Технічний борг

| Поле | Значення |
| --- | --- |
| Записів у techdebt.csv | 3 |
| Разом годин на повернення | 8 |
| Стеля годин мого варіанта | 1040 |
| Борг у відсотках від стелі | 0,77% |
| Рішення pay_now / pay_later / accept | 1 / 1 / 1 |

Стеля годин V11:

(0,25 + 0,5 + 1 + 1 + 0,5) × 8 × 40 = 1040 годин.

Частка боргу:

8 / 1040 × 100 = 0,77%.

Борг виник у документації та способі підтримки матеріалів. D-01 стосується суперечливих пояснень блокера S-03. D-02 - повторення підсумків спринтів у кількох розділах, через що зміна одного результату потребує кількох ручних правок. D-03 - свідомо залишеної ручної звірки беклогу та карток.

Незавершена історія не є технічним боргом. Тому перенесення S-03 між спринтами не записане окремим пунктом боргу.

Для D-03 я прийняла рішення accept. За невеликої кількості навчальних історій ручний чекліст є прийнятним, якщо перевірка виконується перед Review. Рішення перегляну після першої пропущеної невідповідності або значного розширення беклогу.

Замовнику пояснила б це так: суперечливі записи змушують повторно з’ясовувати причини затримок, а повторення однакових підсумків збільшує час оновлення звіту. Виправлення цих місць допоможе швидше підтримувати документи та зменшить кількість помилок у наступних змінах.

## 5. Подія курсу

| Поле | Значення |
| --- | --- |
| Дата події | Потребує звірки з lr15_event.md |
| Оцінка обсягу зміни | Не розрахована без повного тексту події |
| Це від обсягу першого релізу | Не розраховано |
| Рішення | Ще не ухвалено |
| Рядок журналу | Буде доданий після опрацювання події |

Завершення другого спринта не означає автоматичного виконання події курсу. Для рішення потрібні повний текст вимоги, умови спонсора та оцінка її впливу на перший реліз.

Що змінилось у беклозі: за подією поки нічого. Після її читання потрібно визначити нові або змінені історії, оцінити їх тим самим способом, що й на ЛР8, та порахувати частку зміни від початкового обсягу REL-1.

Що змінилось у плані: за подією schedule.csv і roadmap.csv поки не оновлено. Прийнята зміна потребуватиме листових вузлів WBS із годинами та відповідного оновлення календаря. При обміні обсягу потрібно перенести також роботи історій, які вийдуть із першого релізу.

Що змінилось у реєстрі ризиків: у первинному реєстрі передбачено R-07 щодо збільшення обсягу. Після отримання повного тексту події його потрібно уточнити та визначити, чи виникають додаткові ризики.

Що сталося з прогнозом ЛР9: у сценарії завершення двох спринтів використовується velocity 11 і 16 SP. Фактичний points_done другого спринта вноситься лише після огляду. Після рішення за подією потрібно перерахувати forecast.csv для актуального обсягу REL-1 та залишку незавершених історій.
